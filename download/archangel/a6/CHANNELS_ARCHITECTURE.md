# Archangel a6 channel boundaries

## Identity and transport

`channel_protocol.py` defines `intersignal.braid.channel.v1`. A creator's Ed25519 key, random nonce and domain-separated hash establish the channel ID; an Ed25519 signature binds the immutable descriptor. A name is display metadata. Import does not subscribe or grant permissions.

`braid_channel_note` in the signed Braid manifest contains the descriptor, stable note ID, content SHA-256 and bounded origin type. `semantic_capsule.prepare` validates content binding before Phase B. Publisher permission is enforced in Messenger before receiver processing. The transport is not the channel authority.

Direct sends require approved mTLS peers advertising `channels.v1`. The independent receiver additionally checks its own publisher subscription. Exported frames and reconstructed optical chunks use the same signature/policy path without pretending an optical transfer has a TLS certificate. Old peers can still perform ordinary retained handoffs; they cannot silently be selected as channel-capable destinations.

The retained optical encoder can be used explicitly, from the installed runtime, without executing the payload:

```python
from pathlib import Path
import json
from braid_client.qr_engine import chunk_binary_frame
raw = Path('channel-note-export.brad').read_bytes()
chunks = chunk_binary_frame(raw, max_chunk_size=120)
Path('channel-note-chunks.json').write_text(json.dumps(chunks, indent=2))
```

This generates QR payload strings, not camera evidence. The channel Notes view exports a self-contained offline QR reel HTML file. Its Start/Pause/Previous/Next controls render those encoded matrices without network requests. Advanced workspace > Receive by camera handles reconstruction; physical optical UAT remains required. A received channel frame enters `MessengerService.receive`, irrespective of the file/optical route. CLI configurations outside Messenger retain their explicit operator policies; do not assume generic legacy CLI intake creates a channel subscription.

## Persistence and authority

The additive `c6_*` SQLite tables contain descriptors, receiver-local policies, immutable reviewed notes, object mappings, publisher/note deduplication, conversations, answer records and automatic-attempt history. There are no credentials in a public channel card. TLS/signing identities are not regenerated by migration.

A reviewed local note is signed and committed through the existing receiver validator and Semantic Field. Remote delivery remains separately acknowledged. Export is possible only after a recorded local commit. A transport-confirmed outcome is not represented as receiver acceptance or indexing without the relevant evidence.

The sender's existing delivery ledger is still authoritative for per-recipient retry locks. Channel note identity is frozen before transmission. Automatic dispatch never retries an earlier automatic-attempt identity after uncertain completion or startup. Changed recipient permissions do not expand a frozen send. Already-started calls can complete after an operator pauses.

## Model boundary and exact counts

`search_semantic_field` and `reconcile_semantic_field` now accept an optional allowed-object set. Filtering occurs before ranking, deduplication and conflict clustering. Defaults preserve the legacy operator workflow.

Channel chat calls local Ollama with ordinary text messages. The prompt contains the exact selected atoms and a reconciliation envelope, plus bounded eligible conversation history. Historical source atoms are revalidated against current field bundles and permission scope. Changed scope resets supplied history; prior UI turns remain an audit record. A known conflicting sibling that will not fit makes this path fail explicitly instead of disappearing.

`shared_note_count` is the cardinality of the exact `supplied_notes` atom list, deduplicated by atom ID. Repeated references in reconciliation do not inflate it. Each source object and its channel/publisher label is retained. Stored context/message hashes permit checking the constructed request; the metric does not claim attention measurement or truth. A deterministic guard fallback remains distinguishable from a published model draft.

## Privacy and automation

Mode `suggest` checks configured literal phrases in the newly typed user message and creates a draft only. Mode `automatic_marked` additionally requires locally authorized recipients and an explicit per-conversation checkbox; only text beginning `/note ` may auto-publish. Model completions, received notes, filesystem changes and unrelated app conversations never trigger the publisher. The backend, not just the UI, enforces origin, per-note attempts and rates.

Local `use_in_chat` is separate from send/receive permission. Revocation affects future channel prompts but does not delete earlier text, old answers, or an already-running model context. Ordinary Inbox/Advanced all-field inspection remains an explicit local operator function. These controls are not a multi-user OS sandbox, encrypted-at-rest storage, a semantic classifier, or a general prompt-injection proof.

## Compatibility and boundedness

New ordinary channel chat is available inside Archangel only. Direct/portable channel delivery needs a6 on the receiver. Old a5 content is unscoped and retained unchanged. No public cloud relay enrollment, billing action, public endpoint exposure or third-party frontend modification occurs.

Limits: 64 retained channels, 16 approved destinations per channel, 10,000 locally authored notes, 1,000 conversations, 100 displayed turns per conversation, six recent history turns / 12,000 history UTF-8 bytes, 12,000 selected evidence-text bytes, 6,000 UTF-8 bytes per new note/message, 1-12 automatic notes/hour with at least five seconds between attempts. Metadata/prompt overhead is additional to text budgets. Local disk/inference remains a finite user resource.
