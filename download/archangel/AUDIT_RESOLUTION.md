# Archangel audit resolution

This matrix maps Chef's a4 findings and the additional focused review findings to the implemented change. "Implemented" does not mean native macOS/Windows, actual Tailscale or physical multi-rig qualification has been completed.

| Finding | Archangel correction | Evidence / boundary |
| --- | --- | --- |
| Offline isolated-venv trap | Keep isolation; add pinned, target-bound hash-verified pack generation and offline installation. Explicit validated host reuse is available and visible, never an automatic fallback. | Real fresh Linux venv installed offline, no host-site or `.pth` bridge. Test wheels were reconstructed from installed packages, not official fetched wheel bytes. Native platform packs must still be prepared. |
| SQLite connections left open | A closing transaction context manager covers desktop reads/writes; failure rolls back, finally closes. | Connection is unusable after scope; rollback, repeated FD-count and file-move checks. Native Windows locking UAT remains. |
| Forced subprocess termination | Authenticated Quit and launcher `--stop`; parent cooperatively requests shutdown and waits before a bounded forced fallback. Durable interrupted sends become unknown on restart. | Real loopback HTTP CSRF rejection, two clean process stops, profile restart and lock reacquisition. Cannot guarantee graceful cleanup on power loss or OS kill. |
| macOS Gatekeeper / lost execute bit | Document supported Python invocation, per-item OS approval and restoring only the launcher's execute bit; preserve Unix executable mode in ZIP. | Shell syntax/archive mode checks. No Developer ID signing or notarization is claimed. |
| Overlay/APIPA/IPv6 rejected | Coordinate numeric address discovery, card intake, bind policy and clients. Explicit overlay scope requires TLS; direct-link IPv4 and IPv6 ULA/loopback supported. | Address accept/reject tests, overlay no-public-fallback test, real IPv6 loopback bind. Actual adapters/overlays remain physical UAT; scoped IPv6 link-local stays deliberately unsupported. |
| DHCP/network change | Warn on missing local address; update address without rotating signing/TLS identity, route or history. Require signed revised cards on peers. | Endpoint update preserves state; card monotonicity, stale/racing approvals and post-revocation rollback tests. |
| Missing mTLS admission | Approved client certificates and exact hash admission before Braid parser; bind actual frame signer to TLS identity; exact receiver pin on send. | Real loopback uncertified-client refusal, signer mismatch, certificate-pin mismatch and revocation tests. | Partial multi-recipient delivery | Durable content-bound per-recipient handoff ledger, not only checkbox removal; successful/unknown/in-flight locked across restarts. | Loopback duplicate/restart/concurrency checks; fixture-backed production UI reload/partial retry checks. | Strong route ingestion protections | Retain ZIP traversal/symlink/duplicate limits, hash binding, finite bounded numeric arrays and safe NPY-header checks. | Existing malicious-card/route tests retained. No trust implied by a self-signature without operator fingerprint comparison. |

## Important policy decisions

A hash manifest is integrity evidence, not an independent publisher signature. Offline support is not a claim that one ZIP contains all third-party platform runtimes. Address-only changes do not silently authorize certificate/route replacement. Unknown outcomes do not become failed deliveries. Phase A validation, Phase B acceptance and semantic indexing remain different facts. Private files are access-controlled, not encrypted at rest by this release.

All source and regression changes are included in the source archive and a4-to-Archangel patch. Keep the physical acceptance matrix in UAT_ARCHANGEL.md separate from the automated evidence in QA.md.
