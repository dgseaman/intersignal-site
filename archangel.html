01  /  Before you start

Two rigs. One private network.

Keep the computers on the same private LAN for this first test. This guide does not require a relay account or public port forwarding. Do not expose the browser UI or the receiver to the public internet.

On each rig, have standard CPython 3.10 through 3.13 installed. Python 3.14 and free-threaded builds are outside this release’s dependency target. Python must include venv, ensurepip, SSL, and SQLite support. Official Python downloads.

Install and start local Ollama. Then provision the embedding model on each rig:

ollama pull all-minilm

Get Ollama · Official quickstart. Model weights are downloaded separately; they are not inside the Archangel ZIP.

A local chat/generation model is needed on the receiver for Channel Chat. The earlier a5 Cobalt demonstration used mistral:latest. An existing suitable local model can be selected instead; a different model is another configuration to test. To reproduce the model choice, provision Mistral on the receiver:

ollama pull mistral

This can download substantial model weights. Check storage and memory before doing so. Mistral model page.

The launcher installs its pinned Python dependencies into a local isolated environment. No manual virtual-environment setup is required. A cold first launch needs internet access unless you have prepared the documented offline dependency pack. Do not assume the small ZIP is a complete offline installer.
02  /  Open on both computers

Extract the whole folder.

Download the same complete ZIP to both rigs. Extract into its own folder; do not run from inside the ZIP, overlay it onto an earlier release, or replace only the Mac command file. You should see start_braid.py beside the platform launchers.

Mac launcher fix included

Extract. Open Start Braid.command.

The Mac fix is already in this ZIP. It skips an unsupported default Python, finds a supported installed runtime, and prints its selection.

sh "Start Braid.command"

Terminal alternative: run the command above inside the extracted folder. Python must already be installed. No global Python setting is changed. Mac security guidance.

Linux launcher included

Open the extracted folder in Terminal.

Right-click an empty space in the folder, choose Open in Terminal, and run:

sh "Start Braid.sh"

Run as your normal user, without sudo. The Linux launcher uses your default python3. For an unsupported default, explicitly use an installed supported version, such as python3.12 start_braid.py.

Windows physical testing pending

Choose a supported Python explicitly.

Open the extracted folder in Terminal. With standard Python 3.12 installed, use:

py -3.12 start_braid.py

Use -3.13 instead when that is your installed supported version. Start Braid.cmd is also included, but uses the default runtime. This is not an Authenticode-signed installer.

Let installation finish. Look for Archangel is ready:, then open the printed local address in that computer’s browser. The port is chosen locally and can differ between machines.

Leave both service terminals open. The browser address beginning 127.0.0.1 is the local user interface, not the address to enter on the other rig.

macOS says it cannot verify the developer

This ZIP is not Developer ID signed or notarized. Verify its source and checksum. For a trusted downloaded item, follow Apple’s per-item Privacy & Security / Open Anyway guidance where available. Do not disable Gatekeeper globally or recursively strip quarantine attributes. An executable-bit error is distinct from a security warning. The Terminal launcher command above does not require the script itself to have an executable bit. Apple’s current guidance.

03  /  Pair once, both ways

The card connects. The fingerprint verifies.

  1. On the Mac, open Add rig → This rig. Give the machine a name and choose its actual private LAN address, not 127.0.0.1.
  2. Use the installed all-minilm embedding model. Press Prepare and wait for the route to finish calibrating. Then choose Save card.
  3. Do the same on Linux. Transfer each public .braidrig file to the other computer through a channel you trust.
  4. On Linux, open Add rig → Other rig. Choose the Mac’s card. Compare the entire fingerprint with the value on the Mac’s own screen, check the approval box, and click Approve rig.
  5. Import and approve Linux’s card on the Mac in the same way. Do not skip the reverse approval.
The public card carries identity, a pinned certificate, an endpoint, capabilities, and route material. It is not a private key. Pasting only a fingerprint cannot supply the connection information.

Keep receiving paused for the next configuration step. Preparing or importing a card does not, by itself, open the receiver.

03B / One channel identity

Create once.
Import on the other rig.

First finish rig pairing above using current rig cards that advertise channel support. Then create Cobalt on the Mac using + beside Channels.

  1. Open the Mac's Channel settings. Enable Send to for Linux, leave Review each note selected, and save.
  2. Choose Save channel card. Move the signed .braidchannel file through your trusted channel.
  3. On Linux, use + beside Channels > Import channel card. Compare the full channel ID and creator fingerprint. Import the Mac's card; do not create a second channel named Cobalt.
  4. On Linux, open Channel settings. Enable Receive from for the Mac and Allow this channel's notes in local chat. Save. Keep automatic sharing disabled for the first test.
Same name does not mean same channel. The signed card identifies the channel. Importing it grants no sending, receiving, or chat-use permission automatically; each rig controls its own choices.
04 / Linux only

Choose the local model.

Open #Cobalt > Chat. Select an already-installed generation model in Local model, or use Find models to refresh the list. Do not select all-minilm; it is the embedding model.

Enable Use shared notes for this conversation. That control does not override Channel settings: the channel must also permit local chat use. Leave the topic and automatic-send toggles off for this first pass.

If no chat model appears, start Ollama and provision an appropriate local model before continuing. The channel chat lives inside Archangel; an unrelated LM Studio or terminal chat does not automatically consult the channel.

Start receiving on Linux using Add rig > Connect > Start receiving or the Receiving paused top-bar control. Confirm it says Receiving, then check the connection from the Mac. The direct listener defaults to port 8746; allow it only on the intended private network. A connection check is not a delivery receipt.

05 / Mac only

Review one note.
Then share it once.

  1. On the Mac, open #Cobalt > Share a note. Enter the title Archangel channel handoff and the exact text below.
Project Cobalt's launch color is amber.

Do not paste the sentence into Linux. Its copy should arrive through Braid.

  1. Click Review destinations. Check the exact text and that Linux is the intended recipient.
  2. Click Confirm & share note once. Inspect the local commit and each remote result separately. The text is now fixed for this handoff.
  3. On Linux, open #Cobalt > Notes & activity. Check the received note and its indexed status. The original Inbox receipt remains available.
Local indexing is not remote delivery. A note with no destinations is stored locally only. A draft is neither indexed nor transmitted. Stop on an unconfirmed result; do not create another note merely to bypass its delivery lock.

06 / Linux only

Chat normally.
Inspect what the answer used.

After remote acceptance and indexing, open #Cobalt > Chat with the local model selected and Use shared notes enabled. Ask:

What is Project Cobalt's launch color?

The answer should identify amber. Expand the receipt beneath it:

Using 1 shared note#Cobalt · originating rig · exact evidence

Inspect the exact text, channel, source object, arrival time, and generation branch. The count is unique exact source atoms actually supplied, including history-grounding and conflict material where applicable. One long handoff can contribute several atoms; identical atoms count once. It is not a truth or attention score.

These checkboxes are an unsaved browser aid, not a certification or uploaded test record.

You can continue the conversation or choose New chat. Disabling shared notes or changing channel permissions resets the supplied conversation window, while leaving earlier turns visible. No shared input means No shared notes used.

Stop here for the first pass. Record the outcome before testing automatic notes, reverse direction, restart persistence, conflicts, optical transfer, or other operating systems.

New in 1.8.1 / Ordinary Messenger handoffs

A new message starts blank.

Share summary, the welcome compose action and keyboard N open a blank Write step with a new handoff identity. Choose the destination, enter a subject and source text, select Use exact text or Make summary, inspect Review, then click Send summary once.

To resume old work, open Drafts and select the saved item explicitly. Its original identity and delivery locks remain. New message inside the composer saves nonempty work and starts blank; it never copies a signed delta into a new send identity.

X, Escape and Save draft close without sending. An empty new message leaves an older saved draft untouched. Discard draft asks before deleting only the draft, not received notes, Sent history or delivery records. There is still one saved-draft slot: replacing a different draft asks for confirmation, and cancelling leaves the current text open.

Never send an old note just to dismiss it. A new message is not a way to resolve an uncertain previous receipt. During a running send or summarization, reopening another composer is blocked until the job finishes.

These ordinary handoffs are available in Inbox and Shared field. They are not silently assigned to a Channel. To share project-channel notes, use the channel workflow above.

07  /  Diagnose the stopped step

Keep the good state. Find the snag.

The channel is present, but a note is missing or chat uses none

Compare the full signed channel ID, not just the name. Confirm current rig cards, Receive from permission for the sender, channel use-in-chat permission, and the conversation's Use shared notes toggle. Drafts and legacy a5 handoffs are not channel notes. A local sender commit does not prove a remote accepted-and-indexed receipt.

0 indexed items / ERR_FIELD_NO_RELEVANT_ATOMS

The current field has no relevant indexed material for that question. First check whether Confirm & share note was pressed and the remote recipient was selected. Inspect Notes & activity and the original Inbox/Sent receipt. Check the channel ID, allowed publisher, and use-in-chat settings. Do not infer a transport or model failure from the later query error alone. Do not repeatedly send, reinstall, re-pair, or click Index retained state before understanding the receipt.

Python version is outside 3.10–3.13

On a Mac, use the included corrected Start Braid.command, not a command file copied from the original a5 ZIP. It searches standard installed locations. On Linux, choose an installed supported executable explicitly, such as python3.12 start_braid.py. On Windows, use py -3.12 start_braid.py or another installed supported minor. Those commands do not install Python. Install a supported runtime first if none exists.

The Mac launcher cannot find a supported complete runtime

Install standard CPython 3.12 or 3.13 from a trusted source, or explicitly choose an existing interpreter using BRAID_PYTHON. A read-only check is sh "Start Braid.command" --runtime-info. A missing venv or ensurepip component may require your operating system’s matching Python environment package. Do not change system aliases or launch Braid as root.

No completion model / only an embedding model is listed

Start local Ollama and check ollama list. Provision a local chat/generation model, use Find models in Channel Chat, and select its exact name. Enable shared-note use only for the intended channel. The retrieval test can be inspected separately; all-minilm is not a replacement for a completion model.

Receipt not confirmed

An absent acknowledgment does not prove the message was absent at the receiver. Do not resend or create a new message to get a green status. Inspect the receiving inbox and the sender’s detailed receipt. Successful, in-flight, and uncertain recipients are locked for that handoff; that is intentional.

A connection worked, then the network address changed

Use Settings & tools → Network address → Update address for an actually assigned private address. Export the refreshed card and approve it on the peer. This preserves identity and history. Do not rotate keys or enable a public/wildcard bind. Overlay address support does not create a VPN or prove a WAN connection.

The Linux command cannot find Start Braid.sh

The terminal is probably outside the extracted folder. Open the folder containing Start Braid.sh and start_braid.py, right-click empty space, choose Open in Terminal, then run the command. Do not substitute a guessed Downloads path or create a new profile to work around a folder-location issue.

Only Apple touch-icon requests show 404

Those requests concern optional browser icons, not receipt or semantic-field processing. Distinguish them from failures on the actual page assets, API, receiver, or transfer. Use the handoff receipt to diagnose a send, not a missing touch-icon log entry.

For help, send the operating system, Python version, exact action, and error or receipt screenshot to hello@intersignal.ai. Do not send private keys, enrollment tokens, sensitive context, or an entire profile.

08 / Preserve your working rigs

Keep your identity. Start fresh messages.

Version 1.8.1 is a complete integrated release. The corrected composer and supported-Mac-runtime discovery are already included; there is no separate repair package to install. It does not merge the optional a7 Resilience preview. Quit the older client through Settings & tools > Quit Archangel or Control-C, then make a complete external profile backup.

Extract the whole 1.8.1 bundle into a new directory and use its launcher. Your existing identity, contacts, channels and accepted notes stay in the standard profile. If an older version is still running, 1.8.1 asks you to quit it rather than opening its old window. The runtime is version-specific, and the launcher takes a new desktop/trust snapshot. That snapshot does not include the entire semantic inbox.

No new card exchange or channel recreation is required solely for this a6-to-1.8.1 correction. Do not run two versions against one live profile. The upgrade instructions are not a direction to downgrade a live a7 preview profile; keep its corresponding complete backup and separate workflow.

Check for 1.8.1 beside Settings & tools. Open Share summary, verify it is blank, close it, and reopen. Resume Drafts explicitly to inspect older work. Then send a genuinely new harmless note and inspect the receipt. Detailed upgrade and offline guide.

Optional / After the reviewed path works

Suggestions are not permission.

Review before sharing is the default. Suggest topic notes uses your configured literal, case-insensitive phrases to create a local draft from a new user message. It does not transmit the draft or ask a model to rewrite it.

Automatic marked notes requires authorized destination rigs and an hourly limit in Channel settings, plus Allow automatic /note sends in this chat. Only a newly typed message beginning with /note is eligible after the local response succeeds. Ordinary conversation, model replies, incoming notes, and other apps never auto-forward.

/note Project Cobalt's launch color is amber.

Automatic sends have durable attempt records, rate limits, and pause controls. Restart does not replay unfinished automatic work. A started network call may finish after pausing. An uncertain result stays locked; do not manufacture another note to force a green receipt.

Explore conflicts shows locally permitted competing claims within the channel. It does not author a formal resolution or erase earlier claims. Notes and similarity are not truth.

Optional transport / Included in the free client

Same signed note.
Another path.

After a channel note is locally committed, use Export signed note or Save QR reel beside it in Notes & activity. A signed file can be imported from Channel settings on another compatible rig. The offline HTML reel cycles the same signed payload as QR chunks when you press Start reel.

On the receiving compatible rig, use Advanced workspace > Receive by camera for QR collection. Reconstructed frames enter the same channel admission checks. The receiver needs the same channel card, an approved publisher, and explicit receiving permission. Switching paths does not bypass channel-note deduplication.

Displaying or exporting is not delivery. A reel, a reconstructed chunk set, or a saved file is not proof of receiver acceptance or indexing. Inspect the receiver's result. Camera permission, compatible decoders, and display conditions need physical testing; optional camera dependencies are not bundled in the core installer.

No membership or Intersignal relay is required for these paths. The a5 video used LAN; it is not a physical QR test. Production channel-aware Managed Relay remains separate integration and testing, not a service activated by this download.
