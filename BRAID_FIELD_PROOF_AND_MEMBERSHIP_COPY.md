# Braid Semantic Field Proof and Membership Copy

## General-audience behavioral proof

On September 2, 2026, a Mac sent three small signed Braid objects to a Linux receiver. Together, those objects contained five exact statements: four relevant to an invented operating rule called Kestrel Run, and one unrelated statement about archive maintenance.

The Linux receiver committed those statements into its own 384-dimensional Semantic Field. When asked about Kestrel Run, it retrieved the four relevant statements, left out the unrelated fifth statement, recognized that threshold values 73 and 75 occupied the same semantic neighborhood, and flagged the changed number as a possible conflict. It retained the exact source and provenance of both values.

The Linux node then built a fresh 227-byte context for a local Qwen 7B model. The original conversation was not replayed.

This is the behavioral distinction from a shared text pad. A text pad can hold all five lines. Braid gave the receiving computer a persistent, queryable semantic index that selected what mattered, suppressed unrelated material, preserved a conflict, and reconstructed local context for a new inference call.

The test also exposed an important boundary. The Semantic Field retrieved and reconciled the evidence correctly, but the local 7B completion model still chose 73 instead of preserving the unresolved 73-versus-75 conflict. Braid does not make a completion model infallible. The next engineering step is to pass reconciliation constraints into generation through a more deterministic evidence envelope.

### Evidence summary

- 5 exact semantic atoms committed on Linux.
- 4 question-relevant atoms retrieved.
- 1 unrelated atom excluded from generated context.
- Threshold values 73 and 75 grouped and marked as a possible numeric conflict.
- Exact text, source-object digests, and field provenance retained.
- Fresh receiver-local context reconstructed.
- Whole transcript replay: false.
- Completion-model conflict handling: still requires tightening.
